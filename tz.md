# Заводим проект

Библиотека для моковых данных - https://github.com/serpro69/kotlin-faker

### Основные фичи

1. Онлайн-регистрация и оплата
   Пользователь заранее бронирует номер онлайн, выбирает удобный способ оплаты и вводит личные данные.

2. Быстрая проверка
   Возможность быстрой регистрации прямо в приложении перед прибытием, просмотр информации о номере, времени уборки, доступ к карте отеля.

3. Электронный ключ
   После бронирования гости получают виртуальные ключи-карты на телефон для открытия дверей номера, используя NFC-технологию.

https://developer.android.com/develop/connectivity/nfc/nfc

4. Информация о гостинице
   Подробная карта гостиницы, контактная информация персонала, расписание мероприятий внутри отеля
   (расписание хранится в JSON-файле в assets или в data-классах, опционально можно реализовать загрузку из XLS)

5. Услуги
- трансфер (автобус с расписанием, аренда авто, самокатов с картой)
- спа-центр и фитнес-зала (расписание, статистика, регистрация онлайн)
- экскурсии
- уборка номера
- прачечная
- Ресторан
  меню, Заказ в номер, пересылка на сервисы доставки, карта Ближайших ресторанов

6. Раздел с Оплатой услуг
   Быстрое оформление платежей за дополнительные услуги (из раздела 5): экскурсии, массаж, трансфер, прачечная и др., оплата парковочного места.

Вывести отдельный экран, который будет принимать данные об услуге. Выводим платёж и даём тайм-аут на 5 секунд для эмуляции обработки платежа.

7. Обратная связь
   Гость может оставить отзыв о своем пребывании в отеле, оценить качество обслуживания и удобства проживания.

Функционал написания отзыва с возможностью поставить оценку. Оценки от других пользователей должны быть реализованы через мок-объекты.

8. Персонализированные рекомендации
   Приложение предложит персональные рекомендации на основании предпочтений клиента, истории предыдущих заказов и отзывов.

На начальных этапах (до реализации всех фич) показывать случайные рекомендации. После реализации каталога услуг и истории заказов - персонализированные рекомендации на основе истории пользователя.

Ниже представлено структурированное техническое задание (ТЗ) на разработку мобильного приложения для Android. Документ составлен с учетом требования использования моковых данных (Mock Data) для последующей легкой замены на реальные API-запросы.

# Техническое задание (ТЗ) на разработку мобильного приложения «Отель»

## 1. Цель проекта
Разработка Android-приложения для автоматизации взаимодействия гостя с отелем. Приложение должно обеспечивать полный цикл обслуживания: от бронирования номера и заселения до заказа дополнительных услуг и обратной связи.

## 2. Технические требования к реализации
*   **Платформа:** Android (минимальная версия API: уровень 26 / Android 8.0).
*   **Язык разработки:** Kotlin.
*   **Архитектура:** MVVM (Model-View-ViewModel) с использованием Clean Architecture.
*   **Работа с данными:** Реализация репозиториев (Repository pattern) с двумя источниками данных:
  1.  **MockDataSource (фейковый):** Зашитые JSON-файлы в assets или объекты в памяти (In-Memory). Используется по умолчанию.
  2.  **RemoteDataSource (удаленный):** Заглушки (интерфейсы) для будущей замены моков на запросы к серверу (REST API).
*   **UI:** XML-верстка.
*   **Навигация:** Jetpack Navigation Component.
*   **Асинхронность:** Kotlin Coroutines + Flow.

## 3. Функциональные модули (Экраны)

### 3.1. Онлайн-регистрация и оплата (Бронирование)
*   **Экран:** Экран выбора номера / бронирования.
*   **Функционал:**
  *   Просмотр списка доступных номеров (мок-данные: тип номера, цена, фото).
  *   Выбор дат заезда/выезда (стандартный `DatePicker`).
  *   Форма ввода личных данных гостя (ФИО, телефон, email, паспортные данные).
  *   Выбор способа оплаты (карта, наличные).
  *   Кнопка «Забронировать».
*   **Моки:** Список номеров, данные пользователя по умолчанию (для автозаполнения).

### 3.2. Главный экран (Быстрая проверка / Dashboard)
*   **Экран:** Основной экран после авторизации/бронирования.
*   **Функционал:**
  *   Отображение текущего статуса бронирования.
  *   Информация о номере: название, этаж, время уборки.
  *   Виджет быстрых действий (Карта, Электронный ключ, Мои услуги).
*   **Моки:** Информация о текущем номере, расписание уборки (например, "Сегодня уборка в 11:00").

### 3.3. Электронный ключ (NFC)
*   **Экран:** Экран «Ключ-карта».
*   **Функционал:**
  *   Отображение графического ключа-карты с номером комнаты.
  *   Инструкция по использованию NFC.
  *   *Приоритет - эмуляция:* При нажатии на кнопку «Приложить телефон», приложение проверяет валидность мок-ключа и выводит уведомление «Дверь открыта».
  *   *Опционально:* Реальная работа с NFC-тегами (если есть время и устройства для тестирования).
*   **Моки:** Эмуляция NFC-тега. Приоритет - обработчик NFC срабатывает по нажатию кнопки. Реальное NFC - опциональная фича.

### 3.4. Информация об отеле
*   **Экран:** Карта и Контакты.
*   **Функционал:**
  *   Карта этажей (изображение).
  *   Контакты ресепшн, службы поддержки.
  *   Расписание мероприятий.
  *   *Хранение расписания:* Приоритет - JSON-файл в `assets` или data-классы с мок-данными. Опционально можно реализовать парсинг XLS-файла (требует подключения Apache POI или аналога).
*   **Моки:** JSON-файл или data-класс с расписанием мероприятий. Картинка карты отеля.

### 3.5. Услуги (Каталог)
*   **Экран:** Вкладки (ViewPager) с категориями услуг.
  *   **Трансфер:** Расписание автобусов (мок-таблица), аренда авто/самокатов (карта с мок-точками парковок).
  *   **SPA и Фитнес:** Расписание, кнопка онлайн-записи.
  *   **Экскурсии:** Список доступных экскурсий с ценами.
  *   **Ресторан:**
    *   Опционально - меню (категории + блюда). Кнопка «Заказать в номер» (переход к оплате).
    *   Кнопка «Доставка» (открывает ссылку на внешний сервис доставки в WebView или просто переход в браузер).
    *   Карта ближайших ресторанов (Google Maps или Яндекс Карты с мок-метками).
*   **Моки:** Все списки услуг, расписания, меню зашиты в JSON или data-классы.

### 3.6. Оплата услуг
*   **Экран:** Платежный шлюз (эмуляция).
*   **Функционал:**
  *   Принимает данные из раздела «Услуги» (название услуги, цена).
  *   Отображает счет: "К оплате: 1000 руб.".
  *   Кнопка «Оплатить».
  *   При нажатии на кнопку запускается таймер на 5 секунд с индикатором прогресса (ProgressBar) и текстом «Обработка платежа...».
  *   По истечении таймера выводится всплывающее сообщение (Toast/Snackbar): «Успешно оплачено». Можно осуществить переход на экран забронированных услуг.
*   **Моки:** Любые переданные данные об услуге отображаются как есть.

### 3.7. Обратная связь (Отзывы)
*   **Экран:** Мои отзывы / Оставить отзыв.
*   **Функционал:**
  *   Форма: поле ввода текста + рейтинг (RatingBar).
  *   Кнопка «Отправить».
  *   **Моки-отзывы:**
    *   При входе в раздел отображается список мок-отзывов от других гостей (автор, дата, оценка, текст).
    *   После отправки новый отзыв пользователя добавляется в список отзывов сверху (имитация обновления данных).
  *   **Хранение отзывов:** Приоритет - хранение в памяти (In-Memory). Опционально можно использовать Room для персистентности написанных пользователем отзывов.

### 3.8. Персонализированные рекомендации
*   **Экран:** Виджет на главном экране или отдельный экран "Рекомендуем".
*   **Функционал:**
  *   Алгоритм имитации рекомендаций.
  *   Механика: На основе "истории предыдущих заказов" (мок-история, зашитая в профиле пользователя) и проставленных ранее оценок, приложение отображает блок с услугами.
  *   Пример: Если в истории есть посещение SPA, рекомендуем массаж.
*   **Моки:**
  *   `UserPreferences` (мок-объект), который содержит массив ID ранее заказанных услуг (например, [1, 3, 5]).
  *   Если пользователь ни разу не заказывал (пустой массив), показываются случайные услуги (например, "Популярное в отеле").

## 4. Структура данных (Мок-модели)

### 4.1. Организация пакетов (Clean Architecture)
```
app/
├── domain/
│   └── model/              # Domain entities (User, Booking, HotelService, Review, Event)
├── data/
│   ├── model/              # DTO для будущего API
│   ├── repository/         # Реализации репозиториев
│   └── mock/
│       ├── MockDataSource.kt       # Генераторы мок-данных
│       └── assets/                 # JSON-файлы с данными
└── presentation/
    └── ...                 # ViewModels, Fragments
```

### 4.2. Основные модели данных
*   **User:** id, name, email, bookingHistory (List\<Booking>).
*   **Booking:** id, roomNumber, dateStart, dateEnd, status.
*   **HotelService:** id, title, description, price, category (SPA, FOOD, TRANSFER), icon.
*   **Review:** id, authorName, rating, text, date.
*   **Event:** id, title, time, location.

Вы можете придумать другие поля и сущности.

*   Адаптация под разные размеры экранов (планшеты должны выглядеть читаемо).

## 6. Этапы сдачи (Acceptance Criteria)
1.  Приложение запускается без ошибок на эмуляторе.
2.  Реализована архитектура, позволяющая заменить мок-данные на реальные правкой одного класса (подключение другого DataSource).
3.  Расписание мероприятий читается из JSON-файла или data-класса (XLS - опционально).
4.  При нажатии на NFC-кнопку приложение отвечает симуляцией открытия двери (реальное NFC - опционально).
